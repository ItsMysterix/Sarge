# Local Docker Validation Stack

## Overview

This stack allows you to run and validate both the frontend app and backend services locally using Docker containers before deploying to production.

## Quick Start

```bash
# Build and start the entire stack
./scripts/run-local-docker.sh

# Or manually with Docker Compose
docker compose -f compose.local.yaml up -d
```

## Access Points

- **Frontend App**: http://localhost:3003
- **Backend WebSocket**: ws://localhost:3005
- **Backend Metrics**: http://localhost:3006/metrics (requires bearer token auth)

## Configuration

### Environment Variables (compose.local.yaml)

#### Backend Service
- `METRICS_PORT=3000` - Internal metrics server port
- `WS_PORT=3001` - Internal WebSocket server port
- `ALLOWED_ORIGINS` - CORS allowed origins for HTTP requests
- `WS_ALLOWED_ORIGINS` - Allowed origins for WebSocket connections
- `PROM_METRICS_TOKEN` - Bearer token for metrics endpoint (auto-generated)
- `DATABASE_URL` - Placeholder Postgres URL (backend handles connection failures gracefully)

#### App Service
- `PORT=3001` - Internal HTTP port
- `NEXT_PUBLIC_WS_URL=ws://localhost:3005` - Backend WebSocket endpoint (client-side)
- `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY=pk_test_mock` - Mock Clerk key (disables auth for local)
- `CLERK_SECRET_KEY` - Mock Clerk secret (disables auth for local)

### Port Mappings

| Service | Container Port | Host Port | Purpose |
|---------|---------------|-----------|---------|
| backend | 3001 | 3005 | WebSocket server |
| backend | 3000 | 3006 | Prometheus metrics |
| app | 3001 | 3003 | Next.js frontend |

## Authentication Notes

### Clerk Authentication in Local Docker

The app uses mock Clerk keys (`pk_test_mock`) in local Docker mode. This disables real authentication but allows the app to run without errors.

**How it works:**
- `lib/clerk-safe.tsx` checks if `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY === "pk_test_mock"`
- `middleware.ts` bypasses Clerk middleware when using the mock key
- All Clerk-protected features are disabled (users appear as signed out)

### Production Deployment

When deploying to production:
1. Set real `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY` from Clerk dashboard
2. Set real `CLERK_SECRET_KEY` from Clerk dashboard  
3. Clerk middleware will activate and protect routes normally

## Metrics Endpoint Authentication

The backend metrics endpoint requires a bearer token:

```bash
# Get the generated token from the running container
TOKEN=$(docker exec sarge-backend-local printenv PROM_METRICS_TOKEN)

# Access metrics
curl -H "Authorization: Bearer $TOKEN" http://localhost:3006/metrics
```

The token is auto-generated by `run-local-docker.sh` using `openssl rand -hex 16`.

```bash

docker compose -f compose.local.yaml stop

# Stop and remove containers
docker compose -f compose.local.yaml down

# Remove containers and images
docker compose -f compose.local.yaml down --rmi all
```


## Troubleshooting

### App returns 500 error

Check that Clerk keys are set to mock values:
```bash
docker exec sarge-app-local printenv | grep CLERK
```

Should show:
```
NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY=pk_test_mock
CLERK_SECRET_KEY=sk_test_mock_secret_for_local_docker_only
```

### Backend exits immediately

Check logs for errors:
```bash
docker logs sarge-backend-local --tail 50
```

Common issues:
- Missing dependencies (rebuild with `--no-cache`)
- Port conflicts (change ports in compose.local.yaml)

### WebSocket connection fails

Verify backend is listening:
```bash
docker logs sarge-backend-local | grep "WS listening"
```

Check that `NEXT_PUBLIC_WS_URL` points to the correct host port (3005).

### Metrics endpoint returns 401 Unauthorized

Generate and use the correct token:
```bash
TOKEN=$(docker exec sarge-backend-local printenv PROM_METRICS_TOKEN)
curl -H "Authorization: Bearer $TOKEN" http://localhost:3006/metrics
```
