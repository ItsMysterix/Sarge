# Terraform Exporters — Conformance

This document tracks supported/unsupported fields for Terraform JSON export generated by `sarge-core`.

Scope (Phase-2 initial):
- Providers: `hashicorp/aws` (region only; defaults to `us-east-1`).
- Resources:
  - `aws_s3_bucket`: bucket name only (encryption, ACLs, versioning are TODO).
  - `aws_dynamodb_table`: billing mode PAY_PER_REQUEST, key schema/attributes from blueprint (GSIs/LSIs, TTL, streams are TODO).
  - `aws_lambda_function`: name/handler/runtime placeholders only; `filename`, `source_code_hash`, and `role` are emitted as placeholders (packaging and IAM wiring are TODO).
  - Services: represented as `null_resource` with deterministic `triggers` until ECS/EKS support lands.

Out-of-scope (for now):
- IAM roles/policies, S3 bucket policies, Lambda permissions.
- VPC/networking configuration.
- Remote state/backends.

Determinism & Idempotency:
- Filenames are fixed: `providers.tf.json`, `s3.tf.json`, `dynamo.tf.json`, `lambda.tf.json`, `services.tf.json` under `<outDir>/terraform/`.
- Keys are added in sorted order, lists are sorted by name.
- Running export multiple times yields byte-identical files.

Known gaps:
- Lambda packaging/signature hash are placeholders.
- No module layout; all resources are flat at root.
